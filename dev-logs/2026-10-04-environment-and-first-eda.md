## What I found

**The data holds strong signal.** `Class == Business` alone scores **0.7770
accuracy, 0.7257 precision, 0.7995 recall**. That is now the bar any model must
beat, replacing the 0.7203 in the problem statement.

Three findings that were not expected:

1. **Cabin class matters more than any service rating.** Business class is
   satisfied at 4.3x the rate of Eco. `Type of Travel` and `Customer Type` are
   nearly as strong. `disloyal Customer` x `Business travel` = 0.999, so those
   two are very nearly one variable.
2. **`Flight Distance` is the strongest continuous feature**, and satisfaction
   rises monotonically with it: 0.298 / 0.562 / 0.797 across distance bands.
   Nobody would predict that from the column name.
3. **My own "worst service" hypothesis was wrong.** I assumed the worst single
   service would beat the average. It does not: `mean_service_rating` has a
   Cliff's delta of 0.6029, `worst_service_rating` only 0.3234. The average of
   all thirteen ratings is the single most useful derived column in the analysis.

Also: **seven columns carry no usable signal** and are candidates for dropping —
`Gender`, `Gate location`, both delays, total delay, and
`Departure/Arrival time convenient`. All have an effect size below 0.06.

## What I tried that did not work

- **My first quality check demanded zero missing values and stopped the run.** It
  was wrong, not the data. `Arrival Delay in Minutes` has 292 blank rows, which
  `docs/column_dictionary.md` Note 1 already documents as open question 3.
  `.lead/01-DATA.md` says "missing values are *reasonable*", and the failure
  signature it gives is 60% of a key column, not 0.04%. I changed the check to a
  1% threshold and made the blanks a *reported* check rather than a failing one.
  Asserting on them would have blocked the whole project on an open question.
- **Cliff's delta was wrong by exactly +1.** Every value came out above 1, which
  is impossible for a statistic bounded by [-1, 1]. I had written the rank-sum
  formula without its trailing `- 1`. It was caught because the confidence
  intervals went to NaN — the standard error needs a squared delta inside that
  range — and because the corrected values then matched the independent Spearman
  correlations. Before the fix, the "medium or large effect" filter passed
  21 of 21 features, which is a sign the threshold was meaningless. After the
  fix it passes 9 of 21.
- **`LogisticRegression` and `RandomForestClassifier` both refuse NaN**, so the
  first model-ranking cell crashed. Fixed with `SimpleImputer` inside the
  pipeline, fitted on training rows only. Worth remembering: `HistGradientBoosting`
  handles NaN natively, which is one reason `.lead/02-D` recommends it first.
- **The notebook could not find `data/train.csv`.** A notebook's working directory
  is wherever it was opened from. Replaced the relative path with an explicit
  root lookup that raises a clear error if it cannot find the file.
- **I could not confirm the competition metric.** Kaggle returned an error, and
  per the owner's new standing constraint I did not touch the Kaggle API or the
  access token. So the metric stays open question 6.

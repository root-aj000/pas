## Why a random split, which is the rule this dataset does not need

Step 1.7 gives two rules that assume the data has a particular shape:

1. **Split by time, not randomly, when the data is time-ordered.** Not applicable.
   No file in `data/` contains a date. There is no column to sort by, so there is
   no "past" and no "future" to cut between. The label describes the same flight
   as the features in the same row — see [label_definition.md](label_definition.md).
2. **Keep the same entity out of both sets.** Not applicable. There is no entity.
   Each row is one flight by one passenger, and no passenger identifier exists
   anywhere in the data, so there is no group to keep together.

**A stratified random split is therefore the correct choice, not a shortcut past
the rule.** It is stratified on `satisfaction` so the base rate is identical in
all three sets. Without stratification, a 15% test set could drift by a
percentage point and every score would wobble for a reason that has nothing to
do with the model.

## Rules that still apply

- **The test set is opened once**, at the end, after the settings are frozen.
  `.lead/01-DATA.md` Step 1.7 rule 3.
- **Nothing is scaled or fitted on validation or test.** `.lead/01-DATA.md` Step
  1.7 rule 5. Every imputer, encoder and scaler is fitted on train rows only.
- **A new test set for every retrain.** `.lead/06` Step 6.3 says never reuse it,
  or the score keeps looking fine while the model quietly worsens.

## What is deliberately not here

- **No time-based holdout.** There is no time axis to hold out.
- **No group-by-passenger holdout.** There is no passenger identifier.
- **No stratification on anything except `satisfaction`.** Stratifying on a
  feature would change the marginal distribution of that feature between sets and
  make the comparison dishonest.
